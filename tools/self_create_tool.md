# 自主工具创建规范

## 原则
1. 遇到能力缺口，先分析需求，再设计工具，最后实现。
2. 工具必须可复用，有清晰的输入输出。
3. 创建后需集成到系统主流程，确保能被调用。

## 步骤
1. **识别缺口**：当前系统缺少什么能力？（如：解析特定格式、批量处理、复杂计算）
2. **设计接口**：输入是什么？输出是什么？边界条件如何处理？
3. **实现逻辑**：编写代码，确保健壮性。
4. **集成测试**：在主流程中调用，验证效果。
5. **文档化**：记录工具用途、用法、示例。

## 示例：微信公众号文章解析器
- **缺口**：现有 web_get 无法绕过登录墙。
- **设计**：输入 URL，输出标题、摘要、正文（若可获取）。
- **实现**：尝试多种策略（直接抓取、缓存、第三方服务）。
- **集成**：在消息处理流程中优先调用此工具。
- **文档**：记录在 tools/ 目录下。
